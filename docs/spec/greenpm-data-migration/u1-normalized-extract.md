# U1 — 원장 정규화 추출 스펙

> 상태: 살아있는 계약 (living spec) · 독자: 스펙 작성자 / 오케스트레이터

## 목적 / 의도

그린피엠 운영 원장 엑셀은 사람이 읽도록 만들어진 문서다. 제목행·소계행·병합된 2단 헤더·
빈 서식행이 섞여 있고, 시기가 "11월"처럼 연도 없이 적힌 칸이 있으며, 같은 뜻의 값이
표기만 달리 적힌 경우가 있다.

U1의 의도는 **원장의 사실만 남긴 결정론적 데이터셋을 만들어, 이후 모든 적재 단위가
같은 해석을 공유하게 하는 것**이다. 원장 해석은 여기서 한 번만 일어난다. 이후 단위가
엑셀을 다시 읽으면 해석이 갈릴 수 있으므로, 이 데이터셋이 유일한 입력이 된다.

정규화는 **사실을 바꾸지 않는다.** 금액·수량·거래처명은 원문 그대로 보존하고, 제거하는
것은 소계·서식·중복 헤더뿐이다. 연도가 생략된 시기만 확정 연월로 채운다.

## 언어 · 런타임

호스트에서 실행되는 배치 변환. 원본 엑셀은 읽기 전용으로만 접근한다.

## 의존 도구 · 시스템

- 원장 엑셀 파일 (xlsx)
- Odoo 및 데이터베이스와 무관 — 이 단위는 파일 → 파일 변환만 한다

## 입력

원장 엑셀 1개. 시트 3장.

| 시트 | 사람이 읽는 구조 | 사실 행 |
|---|---|---|
| 매출관리 | 2단 헤더(카테고리 그룹) + 데이터 | 23 |
| 원부자재 | 원자재 구역 / 부자재 구역 / 사용현황 예시 구역 (각 구역마다 헤더 반복) | 15 + 사용현황 4 |
| 외주정산 | 매입처별 구역, 각 구역 첫 행이 소계 | 38 (+ 소계 3) |

## 출력 (계약)

기계가 읽는 정규화 데이터셋. 아래 4개 레코드 집합을 가지며, 각 레코드는 원장의 사실 행
하나에 1:1 대응한다.

### 매출 레코드 (23건)

| 필드 | 원장 출처 | 보장 |
|---|---|---|
| 일자 | 일자 | 날짜, 결측 없음 |
| 거래처 | 사업자명 | 문자열, 결측 없음 |
| 담당자 | 담당자 | 문자열, 결측 없음 |
| 작업명 | 작업명 | 문자열, 결측 없음 |
| 수량 (카테고리별) | 현수막·배너·가로등·어깨띠·기타 | 정수 또는 없음 |
| 총액 | 총액 | 정수, 결측 없음, VAT 포함가 |
| 결제완료 | 결제 | 참/거짓 |
| 발송일 | 발송일 | 날짜, 결측 없음 |
| 발송방식 | 발송방식 | 문자열 |
| 받는곳 | 받는 곳 | 문자열 |
| 결제방식 | 결제방식 | 문자열 |
| 계산서상태 | 계산서 발행 | 문자열 |

### 원부자재 레코드 (15건)

| 필드 | 원장 출처 | 보장 |
|---|---|---|
| 구분 | 구분 | 문자열, 결측 없음 |
| 자재구분 | (원자재 구역 / 부자재 구역) | `원자재` 또는 `부자재` |
| 매입처 | 매입처 | 문자열, 결측 없음 |
| 매입가 | 매입가 (VAT 포함) | 정수 또는 **없음**(2건) |
| 매입일 | 매입일 | 날짜, 결측 없음 |
| 매입량 | 매입량 | 정수, 결측 없음 |
| 잔여량 | 잔여량 | 정수 또는 **없음**(3건) |
| 스토리지 | 스토리지 | `고양`·`백석` 또는 **없음**(3건) |

### 원단 사용현황 레코드 (4건)

1600폭 원단의 사용 내역. 제작물명 · 사용일 · 사용량 원문.

### 외주 레코드 (38건)

| 필드 | 원장 출처 | 보장 |
|---|---|---|
| 매입처 | 매입처 | 문자열, 결측 없음 |
| 구분 | 구분 | 문자열, 결측 없음 (구분이 빈 행 = 소계행이므로 제외됨) |
| 시기 | 시기 | **날짜, 결측 없음** — 월만 적힌 14건은 확정 연월로 채워짐 |
| 정산시기 | 정산 시기 | 문자열 또는 없음 (원문 보존, 해석하지 않음) |
| 금액 | 외주비용 (VAT 포함) | 정수 또는 **없음**(2건) |
| 결제완료 | 결제 | 참/거짓 |
| 비고 | 비고 | 문자열 또는 없음 |

## 핵심 로직 (동작)

### 사실 행과 비사실 행의 구분

- **소계행**: 매입처는 있으나 구분이 비어 있는 행. 사실이 아니라 집계이므로 데이터셋에
  포함하지 않는다. 다만 소계값은 검증에 쓰인다 — 상세행 합계와 일치해야 한다.
- **구역 헤더 반복행 · 제목행 · 빈 서식행**: 데이터셋에 포함하지 않는다.
- **구역 소속**: 원부자재는 어느 구역(원자재/부자재) 아래에 있는지가 그 행의 사실이므로
  `자재구분`으로 명시한다.

### 연도가 생략된 시기의 확정

원장에 월만 적힌 외주 14건은 아래 연월로 확정한다. 근거는 원장 자체다 — 첫 매출이
2024년 10월이고, 세무법인 관리비 11건이 연속 11개월이며 그 소계(1,815,000)가
165,000 × 11과 일치한다.

| 매입처 · 구분 | 원장 표기 | 확정 연월 |
|---|---|---|
| 외주1 · 디자인 | 10월 | 2024-10 |
| DZ원 · 실사 | 11월 / 12월 | 2024-11 / 2024-12 |
| 세무법인 · 관리비 | 11월 / 12월 | 2024-11 / 2024-12 |
| 세무법인 · 관리비 | 1월 … 9월 | 2025-01 … 2025-09 |

일(day)은 해당 월의 1일로 확정한다.

### 사실을 바꾸지 않는다

- 금액은 원장 값 그대로 보존한다. 세액 분리·반올림은 이 단위의 책임이 아니다.
- 거래처명·담당자명은 원문 그대로 보존한다. 동일 실체 판단(예: 표기가 다른 같은 회사)은
  U3의 책임이다.
- 결측은 채우지 않는다. 매입가 없음·잔여량 없음·스토리지 없음은 **결측 그대로** 남기고,
  그 해석은 소비 단위가 자기 계약에서 정한다.
- 정산시기의 "익월초" 같은 표현은 해석하지 않고 원문 보존한다.

### 결정론

같은 엑셀을 몇 번 변환하든 동일한 데이터셋이 나온다. 실행 시각·난수·환경에 의존하지 않는다.

## 검증 단언 (TDD)

- **A. (핵심)** 매출 레코드가 정확히 **23건**이다.
- **B. (핵심)** 매출 레코드의 `총액` 합계 = **5,350,600**.
- **C.** 매출 레코드 중 `결제완료 = 거짓`인 것의 `총액` 합계 = **1,430,000** (2건).
- **D.** 매출 레코드 전건에서 `일자`·`거래처`·`담당자`·`작업명`·`총액`·`발송일`이 결측이 아니다.
- **E. (핵심)** 원부자재 레코드가 정확히 **15건**이며, 그중 `자재구분 = 원자재`가 **8건**,
  `부자재`가 **7건**이다.
- **F. (핵심)** 원부자재 레코드의 `매입가` 합계(결측 제외) = **3,737,440**, 결측은 정확히 **2건**
  (`생분해성 / 600폭`, `종이명찰 단면`).
- **G.** 원부자재 레코드 중 `잔여량` 결측이 정확히 **3건**, `스토리지` 결측이 정확히 **3건**이다.
- **H.** 원단 사용현황 레코드가 정확히 **4건**이다.
- **I. (핵심)** 외주 레코드가 정확히 **38건**이며, `구분`이 결측인 레코드가 **0건**이다
  (= 소계행이 하나도 섞이지 않았다).
- **J. (핵심)** 외주 레코드의 `금액` 합계(결측 제외) = **4,662,129**, 결측은 정확히 **2건**
  (`sh공사 행사`, `인플릿`).
- **K. (핵심)** 외주 소계 검증: 매입처별 상세 합계가 원장 소계와 일치한다 —
  DZ원 = 2,570,129 · 외주1~9 = 277,000 · 세무법인 = 1,815,000.
- **L. (핵심)** 외주 레코드 전건의 `시기`가 날짜이며 결측이 없다. 원장에 월만 적혀 있던
  **14건**이 위 표의 확정 연월과 일치한다.
- **M.** 외주 레코드의 매입처 종류가 **11종**이다 (DZ원 18건 · 세무법인 11건 · 외주1~9 각 1건).
- **N.** 동일 엑셀로 두 번 변환했을 때 두 데이터셋이 완전히 동일하다 (결정론).
