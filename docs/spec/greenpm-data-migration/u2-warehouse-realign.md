# U2 — 창고 재편 스펙

> 상태: 살아있는 계약 (living spec) · 독자: 스펙 작성자 / 오케스트레이터
> 소비하는 접합부: 없음 · 생산하는 접합부: `../_shared/greenpm-master-data-keys.md` (창고명)

## 목적 / 의도

그린피엠은 자재를 **고양**과 **백석** 두 곳에 나누어 보관한다. 원장의 모든 재고 행은 이 둘 중
하나에 속하며, 잔여량 실사도 보관처 단위로 이루어진다.

U2의 의도는 **테넌트의 창고 구조가 실제 보관처와 1:1로 대응하게 만드는 것**이다. 대응이
어긋나면 이후 입고·실사가 실재하지 않는 장소를 가리키게 되고, 재고 화면이 현실과 무관해진다.

현재 테넌트에는 이 회사의 실제 보관처와 대응하지 않는 창고들이 존재한다. 이는 테넌트를
만들 때 다른 회사의 구조가 함께 따라온 결과이며, 그린피엠의 사실이 아니다.

## 언어 · 런타임

Odoo 19 Enterprise · 재고(stock) 모듈.

## 의존 도구 · 시스템

- 테넌트 데이터베이스
- 재고 이동 이력이 없는 상태 — 이 계약은 **이력이 0인 시점에서만 성립**한다. 이동이 이미
  기록된 창고는 구조를 바꿀 수 없다.

## 입력

현재 테넌트의 창고 구조.

## 출력 (계약)

- 창고가 **정확히 2개**이며, 이름이 각각 `고양`, `백석`이다.
- 두 창고 모두 재고를 보관할 수 있는 온전한 상태다 — 각자 자기 보관 위치를 가지며, 입고와
  실사의 대상이 될 수 있다.
- 그린피엠의 사실이 아닌 창고는 남아 있지 않다.

## 핵심 로직 (동작)

- 창고의 존재 이유는 원장의 `스토리지` 값이다. 원장에 등장하는 스토리지는 `고양`·`백석`
  둘뿐이므로 창고도 둘이어야 한다.
- 창고 제거는 **재고 이동·재고 수량이 전혀 없는 창고에 한해** 성립한다. 이동이 존재하는
  창고를 제거하는 것은 사실의 파괴이므로 이 계약의 범위가 아니다.

## 검증 단언 (TDD)

- **A. (핵심)** 테넌트의 창고 총수가 **2**다.
- **B. (핵심)** 창고 이름 집합이 정확히 `{고양, 백석}`이다.
- **C. (핵심)** 각 창고가 자기 재고 보관 위치를 가지며, 그 보관 위치가 **자기 창고의 뷰 위치
  아래**에 있다 (다른 창고 아래 붙어 있지 않다).
- **D. (핵심)** 제거된 창고가 남긴 위치가 없다 — 창고에 속하지 않는 내부/뷰 위치는 회사가
  소유하는 위치(외주생산 위치 · 창고간 경유 위치)뿐이다. 창고 없는 위치를 0건으로 요구하지
  않는다: Odoo는 이 둘을 창고와 무관하게 정상적으로 보유한다.
- **E.** U2 실행 전후로 재고 이동 건수가 변하지 않는다 (실행 전 0건 → 실행 후 0건).
