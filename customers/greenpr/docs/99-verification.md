## 7. 재현 쿼리 (psql)
DB 컨테이너 (`ycerp-db-greenpr`, user/db = odoo/odoo) 에서 직접 확인 가능.

```bash
# 5단계 marker hit 수
docker exec ycerp-db-greenpr psql -U odoo -d odoo -c "
  SELECT 'mail.mail'      AS step, count(*) FROM mail_mail       WHERE body_html  LIKE '%ralph-demo-flow id=greenpr:%' AND body_html NOT LIKE '%greenpr:lead:%' AND body_html NOT LIKE '%greenpr:so:%' AND body_html NOT LIKE '%greenpr:inv:%' AND body_html NOT LIKE '%greenpr:po:%'
  UNION ALL SELECT 'crm.lead', count(*) FROM crm_lead       WHERE description LIKE '%ralph-demo-flow id=greenpr:lead:%'
  UNION ALL SELECT 'sale.order', count(*) FROM sale_order      WHERE note         LIKE '%ralph-demo-flow id=greenpr:so:%'
  UNION ALL SELECT 'account.move',count(*) FROM account_move    WHERE narration    LIKE '%ralph-demo-flow id=greenpr:inv:%'
  UNION ALL SELECT 'purchase.order',count(*) FROM purchase_order WHERE note         LIKE '%ralph-demo-flow id=greenpr:po:%';
"

# SO ↔ invoice 금액 정합 (모든 그룹 합)
docker exec ycerp-db-greenpr psql -U odoo -d odoo -c "
  SELECT s.id AS so_id, s.amount_total AS so_total, m.id AS inv_id, m.amount_total AS inv_total
    FROM sale_order s
    JOIN account_move m ON m.invoice_origin = s.name AND m.move_type='out_invoice' AND m.state='posted'
   WHERE s.note LIKE '%ralph-demo-flow id=greenpr:so:%'
   ORDER BY s.id;
"

# PO ↔ SO 매핑 (origin)
docker exec ycerp-db-greenpr psql -U odoo -d odoo -c "
  SELECT p.id AS po_id, p.name AS po_name, p.origin AS so_name, p.amount_untaxed AS po_untax,
         s.amount_untaxed AS so_untax, ROUND(p.amount_untaxed/NULLIF(s.amount_untaxed,0),4) AS ratio
    FROM purchase_order p
    JOIN sale_order s ON s.name = p.origin
   WHERE p.note LIKE '%ralph-demo-flow id=greenpr:po:%'
   ORDER BY p.id;
"
```

## 8. 알려진 비대칭: greenpr sale tax(id=6) 와 purchase tax(id=22)
greenpr 의 두 10% TI 라벨 부가세는 같아 보이지만 동작이 다르다.

| field | sale tax id=6 | purchase tax id=22 |
|---|---|---|
| name | `10% TI` (한국어 '부가세') | `10% TI` |
| amount | 10.0 | 10.0 |
| price_include_override | `tax_excluded` (net) | `null` (default → gross) |

**결과**: 동일 product 에 sale tax 와 purchase tax 가 모두 붙으면 SO.price_unit 은 net,
PO.price_unit 은 gross 가 된다. 그래서 `PO.amount_untaxed / SO.amount_untaxed` 비율은
실제 단가 비율보다 약 5% 낮게(net=gross/1.10) 떨어진다.

**검증 정책**: PRD AC "PO 단가 = SO 단가 × 0.6~0.7" 의 1차 기준은 line-level
`price_unit` 비율 (§6.C4-3 ✅ 22/22 통과). amount_untaxed 비율은 정보성 (§6.C4-3b)
으로만 기록 — 면세 품목은 net=gross 라 untax_ratio = pu_ratio 동일하지만, 과세 품목은
~5% 하향. 후속 테넌트 적용 시엔 sale/purchase tax setup 의 price_include 정책을
일치시키거나, US-009 의 `derive_price_ratio` 결과를 net→gross 변환(× 1.10)해서
PO.price_unit 에 넣는 옵션을 추가하면 untax 비율도 일치한다.
